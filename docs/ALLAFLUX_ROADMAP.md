# ALLAFLUX™ Roadmap

## Phase 1 — Foundation (current repository baseline)

- Web creator application
- Generation API
- PostgreSQL generation state/history
- Redis queue
- Worker
- Model gateway
- ACE-Step 1.5 runtime contract
- Audio processing
- Media ingestion
- Object storage integration
- Artist sound profile package
- Generation provenance/checksum metadata

## Phase 2 — ALLAFLUX Identity Layer

- Canonical Artist Record 2.0
- Artist image manager
- AMG registry-code integration
- Artist profile/hero media
- Artist sound-profile resolution at generation time
- Canonical artist-to-track/release relationships

## Phase 3 — Catalog & Media

- Full track/release/album/playlist model
- Media Library synchronization
- Persistent player
- Track-focused playback state
- Video/visualizer relationships
- Search and genre browsing

## Phase 4 — Flux Discovery

- Trending service
- Recommendation service
- Artist affinity
- Catalog ranking
- Search indexing
- Discovery analytics

## Phase 5 — Commerce & Membership Integration

- Explicit track commerce eligibility
- WooCommerce product mapping
- Artist stores
- Digital delivery
- Configurable membership entitlements
- Rewards/engagement integration

## Phase 6 — Production Hardening

- Authentication and authorization review
- Rate limiting
- Idempotent generation jobs
- Retry/dead-letter handling
- Observability
- Automated tests
- CI/CD
- Backup/restore procedures
- Storage lifecycle policies
- Security review
- Rights/compliance review

## Release Rule

A feature is not considered production-ready merely because its UI exists. Each release must identify what is implemented, what is simulated, what requires external infrastructure, and what remains gated by testing or compliance review.
